# Start New Projects with a Reusable Terrain Template

A good template saves setup time without deciding the terrain for you.

If every project starts by recreating the same scale notes, graph groups, output nodes, preview profile, and mask area, that structure belongs in a starter file. But the template should stay boring. It should not carry the art direction from the last project into the next one.

> [!TIP]
> Build the template around workflow structure: scale, stages, outputs, profiles, and review notes. Leave the creative terrain decisions empty.

## What belongs in the template

Include the parts that help every project start cleanly:

* a scale note for terrain width, height range, target app, and output intent
* grouped areas for macro shape, erosion, surface detail, masks, color, and exports
* starter output nodes with clear names
* a small mask area for slope, height, flow, deposit, or art-directed masks
* Build Profiles such as `Preview`, `Final`, `Masks`, and any common engine target
* an experiments area kept away from the main route

Those pieces reduce setup friction without forcing one terrain style.

## What does not belong

Do not put finished erosion settings, client-specific paths, old experiments, hardcoded scale, or a hidden Macro library into a general template. That kind of content makes the file feel useful at first, then slowly turns it into a project file with the wrong name.

If a template already looks like a finished terrain, it is probably too specific.

## Build it once, then protect it

Create the graph stages with Groups or annotations. Add the scale note near the top of the graph. Name the starter output nodes. Save the useful Build Profiles. Add a small output checklist near the export area.

Then keep the template clean. When a real project starts from it, save a new project file immediately and do the creative work there.
